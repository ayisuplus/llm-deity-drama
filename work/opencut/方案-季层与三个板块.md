# 大模型神明 · 季层方案

> 2026-11-09 · 讨论稿，未落代码
> 参照物：`work/opencut/样张/工作台样张.html`（4 个视图，可点）

---

## 0. 一句话

**给 OpenCut 加一层「季」，让 24 集住进同一个工程；把前期/生成/后期从三个页面降级成三条车道；外面的 `_canon/` 才能退役。**

---

## 1. 问题有三层，我们一直在错的那层

| 层 | 症状 | 是不是病根 |
|---|---|---|
| 症状层 | 翻 `_canon/` 很恼火 | 不是 |
| 中间层 | 5 个 workspace 并行，信息出不来 | 不是 |
| **病根** | **没有一根贯穿「季 → 集 → 镜」的轴** | **是** |

磁盘上的乱、界面上的散，是同一个病的两个投影：

- 界面散了 → 因为每个概念需要一个地方放，所以开了 5 个 workspace
- 磁盘散了 → 因为每张表需要一个文件放，所以开了 13 个 JSON

**都不是懒，是结构决定的。**

---

## 2. 实测：现在的伤害

```
短剧/大模型神明/项目仪表盘/_canon/     13 个 JSON，2.3 MB

  canon.json      1.1 MB   含 710 处 shots 字段   ← 打包器产出的第四份
  season.json     299 KB   含 608 处 shots 字段   ← 第二份
  governance.json 188 KB
  rules.json      156 KB
  production.json  48 KB
  episodes.json    53 KB   反而最薄，无镜数据
  ... 其余 7 个

.opencut/projects/local-damoshen-ep1/  136 KB   ← 第三份
```

**同一份镜数据，磁盘上至少三处。**

**结论：不是"总库放在外面"的问题，是"没有单一真相源"的问题。**

## 3. 核心决策

### D1 · 工程 = 季，不是集

**决定：** 一个 `.opencut` 工程装 24 集，每集是一条 `TScene`（时间线）。

**理由：** OpenCut 里已经有 `TScene`，而且工程级的 settings 和媒体池正好在 scene 外面：

```
工程  ├─ settings（fps 60 / 16:9）    ← 全季一套，番剧本该如此
      ├─ 媒体池（MediaManager）        ← 全季共享，素材只登记一次
      └─ scenes × 24（各自轨、书签）
```

**收益（这是"丝滑跨集"的字面意思）：**

| 现在 | 改后 |
|---|---|
| 换集 = 换工程 = 重载 136 KB + 媒体池重登记 | 换集 = 换 active scene，秒切 |
| 24 集 = 24 份媒体池，同一素材登记 24 次 | 媒体池只有一份 |
| 季规格要写 24 遍 | 工程级一套 |

**代价：** 24 条 scene 塞一个工程，抽屉列表会很长 → 需要季轴视图（见 D5）。

---

### D2 · 季轴不播放，只排版和连线

**决定：** 季层的"一格"是**一集**；季视图没有播放头，不下到帧。

**理由：** 24 集 × 13 分钟 = 5.2 小时 = 56 万帧。**留着帧精度的季轴没法用。**

**季层要回答的三个问题：**
1. 24 集摆一起，节奏对不对
2. 哪里有跨集连读（音乐、悬念钩子）
3. 哪一集短了 / 长了

**这三件事都不需要帧。**

---

### D3 · 跨集的东西不是"镜"，是"边"

**决定：** 镜永远归属某一集，**禁止跨集镜**。跨集只允许三种边：

| 动作 | 是什么 | 例子 |
|---|---|---|
| **搬** | 一镜换父级 | EP07 的 5-2 挪到 EP08 开头 |
| **引** | 引用，不复制 | EP24 前情回顾引用 EP03 的 3-2 |
| **连** | 一条跨集连续 | 鲸歌底噪从 EP03 尾连到 EP05 头 |

**理由：** 一旦允许跨集镜，每条镜的"父集"就含糊了，集时长、集导出、集审查全部要重算。**边是加法，跨集镜是乘法。**

`hooks`（悬念钩子）和连续性字段在 canon 里已经有了 —— 季层就是把它们画成看得见的边。

---

### D4 · 界面 = 一根轴 + 三个开关

**决定：** 纵栏（结构树 + 对象树）恒定不动；右栏可插拔；三个正交开关：

```
[季 | 集 | 镜]     [一列一镜 | 六轨 | 单镜]     [前期 | 生成 | 后期]
   层级 level            密度 density              阶段 stage
```

**理由：** 你最初抱怨的"5 个 workspace 并行"，答案不是把它们合并，是**它们本来就不是平级页面，而是同一根轴的三种缩放。**

- 「剪辑台」= `density=六轨`，不是独立页面
- 「总库」= `level=季`，不是独立页面
- 「资产审查」= `stage` 过滤出的"卡住的镜"，不是独立页面

**列的单位随 level 变（同一套渲染函数，三档缩放）：**

```
level=季   行 = 六层   列 = 集（24）
level=集   行 = 六层   列 = 镜（15）
level=镜   行 = 六层   列 = 秒
```

---

### D5 · 面包屑 + 双击下钻 + Tab 原地升降

```
大模型神明 › EP03 深两市集 › 1-6 物理外挂皆恐慌
   ↑季          ↑集           ↑镜
```

- **双击任一格 = 下钻**
- **Esc / 点面包屑 = 上浮**
- **Tab = 原地换层级**（位置不变，只变精度）← 这条最重要

**理由：** 换层级如果不保持位置，人就会迷路。这是 `scope` 和 `density` 之外唯一的交互规矩。

---

### D6 · 附：引用要钉到版本级

**决定：** 镜引用 `CH-01#礼服@v3`，不是 `CH-01`。

```
CH-01                     ← 这个人不变
  └ CH-01#礼服            ← 变的是这个
      └ CH-01#礼服@v3     ← 真正会变的是这个
```

**配套三条：**
1. **版本不可变** —— 改图 = 新建 v4，v3 冻结
2. **台账算出来，不存出来** —— 没有"影响清单"文件，靠边实时查
3. **`bump` 是批量重指，不是改内容** —— 内容一字不动，只是版本号 3→4，所以可分批、可回滚

```
opencut asset usage CH-01#礼服@v3 --all
opencut asset bump  CH-01#礼服 --to v4 --scope EP05
```

**理由：** AI 制作和真人制作的真正区别——

|  | 真人 | AI |
|---|---|---|
| 改一个形象的代价 | 重拍 | 重出图 |
| 变化落点 | **素材本身** | **引用** |
| 所以 | 默认快照 | 默认快照 + **显式升级台账** |

**硬话：** 如果一个形象从根上就错了，那是重做，不是引用问题。工具能做的是**知道炸哪几集 / 代价可分批 / 永远能回退**，不是消除"改"。

## 4. 三个板块 = 三条车道，不是三个房间

**你的提议：** ① 前期准备（剧本→故事板）② 生成（资产→关键帧→视频）③ 后期（剪辑，未来调色）

**同意。但必须换个实现方式，否则会退回老病。**

### 为什么不能做成三个互斥页面

**同一集里，1-1 已出片，1-9 还是文字：**

```
1-1  ████████  已出片
1-2  ██████    已出图
1-3  ██        只有文字
```

**阶段是「镜」的属性，不是「页面」的属性。**

### 正确形态：三块是右栏的三种渲染 + 三个默认过滤

| 板块 | 右栏渲染 | 默认过滤 | 成本 |
|---|---|---|---|
| **前期准备** | 一列一镜 + 故事板缩略图 | 文字层未定稿的镜 | **小** |
| **生成** | 资产矩阵 + 产出队列 | 缺资产/缺关键帧/缺视频的镜 | **大** |
| **后期** | 六轨时间线 | 已出片、待排的镜 | **小（已存在）** |

**纵栏不动。切板块只切右栏 + 过滤条件。**

### 而这就是你要的"资产审查"

> **审查的本质不是"过一遍表",是"找出停在前面的镜"。**

颗粒粗细就是阶段，一眼看完 24 集卡在哪。

---

## 5. 三个板块的真实成本，差三倍以上

| 板块 | 要做什么 | 判断 |
|---|---|---|
| **后期** | **已经存在**。只差 scene=集 + 季轴 | 小 |
| **前期准备** | 剧本正文（已是 md）+ 镜的故事板网格 | 小 |
| **生成** | 任务队列、外部服务接口、回挂、重试、成本 | **大，一个子系统** |

**生成板块最容易做成第二个 OpenCut。提前立规矩：**

> **软件只管"要什么、收到了什么"。出图出视频全部交给外部（RunningHub / ComfyUI）。**
>
> **不内建生成器、不内建模型、不内建提示词引擎。只做排队 + 对账。**

---

## 6. 不做的事

| 不做 | 为什么 |
|---|---|
| 一个工程装 24 集全部轨 | 半年做不出来，而且比现在差 |
| 季轴下到帧精度 | 56 万格，没法用 |
| 跨集镜 | 父集含糊，所有统计要重算 |
| 内建生成器 | 变成第二个 OpenCut |
| 引入数据库 | 缺的是一条边，不是存储 |
| 手工维护"影响清单" | 必然腐烂，要算出来 |
| 私有二进制格式 | 软件坏了就打不开，唯一防线是纯文本 |

## 7. 外面的总库怎么退场

**顺序不能反。**

```
先长出季层  →  软件里有了"跨集"这个位置  →  外面的表才可以删
```

`_canon/season.json`（299 KB、608 处镜数据）之所以存在，**是因为软件里没有季层，季只能委屈地住在 JSON 里。**

季层一出来，它就自然退役。**不是"搬进去"，是"它本来该在这儿"。**

### 具体退场顺序

```
第一步  13 个 JSON → 1 个（不改 schema，纯合并 + 全量校验）
第二步  季层吃掉它，工程不再重复存镜数据
第三步  加 level 开关（复用 density 那套）
第四步  写 export，然后删 _canon/
```

### 保留的东西

> **你不该"维护一份人物表",你该"随时能导出人物表"。**
>
> 前者是负担，后者是能力。

**减掉的是"维护",不是"产出"。**

```
opencut export --all --md      # 给配音、给画师、给自己打印、给 git diff
```

3. 来回切几次

- 切回 EP01，15 镜还在不在
- 空 scene 的时长/轨布局，是不是"一集"该有的样子

**这一步能验证的比再聊十轮都多。**

### 第 1 步 · 季层最小可跑

| 做什么 | 在哪 |
|---|---|
| 给 `TScene` 加 `order` / `episode` 字段 | `apps/web/src/timeline/types.ts:21` |
| 抽屉按 order 排序，命名 `EP01..EP24` | `apps/web/src/components/editor/scenes-view.tsx` |

**验收：** 24 个块摆一排，一眼看出每集时长和空缺，双击能进集。

### 第 2 步 · 边 + 阶段

| 做什么 |
|---|
| 加 `edges`（连/引/搬），季视图画出跨集连读 |

**验收：** 一眼看出"哪 3 镜卡在生成"，并且能找到它们卡的原因。

### 第 3 步 · canon 退役

| 做什么 |
|---|
| 合并 13 个 JSON → 1 个（带全量校验） |
| 工程吃进去，不再重复存 |
| 写 `export`，删 `_canon/` |

**验收：** 外面零个需要人打开的文件；`export --all` 能还原出现在的全部信息。

## 10. 名词表

| 词 | 意思 |
|---|---|
| **季 level / season** | 24 集为一个单位，一格=一集 |
| **集 / sequence / scene** | `TScene`，一条独立时间线 |
| **镜 / shot** | 一集内的最小叙事单位 |
| **六层** | V2 叠加 / V1 画面 / A1 主声 / A2 音乐 / A3 音效 |
| **边 / edge** | 跨集关系：连读、前情引用、转场承接 |
| **pin** | 镜指向资产版本的引用 |
| **锚点 anchor** | 当前选中的一格（镜/集/资产版本） |
| **谓词 filter** | 当前过滤条件，如 `CH-01@常态` |
| **两态** | 无谓词=点查（暖色=命中）；有谓词=查询（暖色=命中，其它变灰） |
